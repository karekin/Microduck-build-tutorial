## 本机直接运行

在仓库根目录打开终端。已安装的虚拟环境可以直接使用，不需要连接机器人。

```sh
python3 scripts/local_preflight.py --training
```

它依次运行部署回归、10秒模拟站立、训练回归和CPU短步进，退出码非零表示检查失败。每次新建 `.omx/artifacts/preflight/<时间>/`，保存测试输出、真实状态日志和 `report.json`；不会连接串口或 SSH。报告中的 PASS 只覆盖列出的软件检查。

还要复验训练与导出完整流程时：

```sh
python3 scripts/local_preflight.py --training --training-update
```

只进行1轮PPO更新，保留默认网络与PPO参数。产物在新的 `UNTRAINED_DEMO_NOT_FOR_HARDWARE` 目录，文件和元数据均有标记；不会替换原 `walk.onnx` 或 `velocity.pt`，也不会上传训练日志。1轮更新只验证通路，不能训练出可供实机使用的步态。

单独跑站立：

```sh
microduck/.venv/bin/python microduck/src/sim/sim_main.py \
  --headless --walk --ticks 500 --log logs/standing.jsonl
```

相对 `--log` 路径从 `microduck/` 目录计算，所以上例写入 `microduck/logs/standing.jsonl`；也可传入绝对路径。

复现已录制的低速演示：

```sh
microduck/.venv/bin/python microduck/src/sim/sim_main.py \
  --headless --ticks 750 --walk --policy-immediately \
  --policy-kp 200 --velocity 0.07142857142857144 0 0 \
  --command-delay 2 --command-ramp 2 \
  --initial-height 0.12 --physics-timestep 0.005 \
  --delay-act 0 --delay-vel 0 --delay-gyro 0 --delay-quat 0 \
  --log logs/demo-slow.jsonl
```

`--velocity` 接收归一化输入，前进上限为0.7m/s，因此0.07142857映射为0.05m/s。此演示站立2秒、加速2秒，使用上游机构的高度/时间步/KP200，并显式取消模拟延迟、跳过硬件启动插值。**这些是模拟对照参数，不应直接覆盖树莓派的硬件配置。**硬件默认KP125与膝关节偏移没有改。

有窗口交互查看模型（Mac须使用 `mjpython`）：

```sh
cd microduck
make sim
```

`make sim` 现在默认打开低速键盘模式，使用KP200、初始高度0.12m、时间步0.005s，并取消模拟传感延迟；终端打印实际配置。正常1.5秒启动保留，前2秒保持零速度。第一次按上键将目标前进速度设为0.05m/s，用2秒逐渐加速；连按不会继续提高。下键先减为零，再按最多请求0.025m/s后退。左右键以0.05rad/s步长调整转向目标，上限0.10rad/s，转向也逐渐改变。

### 加速档

在行进时按 `9`，目标上限从0.05提高到0.10m/s，仍以0.025m/s²渐进加速；按 `8` 回到慢档，按 `x` 减速停走。静止时选择 `9` 只选档，不会自行启动，随后按上键启动、再次按上键达到0.10目标。也可一开始选择快档：

```sh
make sim SIM_SPEED=0.10
```

快档使用真实模拟机身航向作为反馈，在策略的转向命令上补偿跑偏，上限0.30rad/s；没有锁住物理姿态或改写策略权重。反馈只在快档前进时生效，`x`、静止、后退、慢档和重置都会取消自动航向追踪；重新前进时以当前方向重新建立参考。它使用模拟真值与无传感延迟，不能直接作为实机控制方案。

原始加速对照中0.10m/s目标虽未倒，但30秒偏航约127°；0.15/0.20档偏航和速度误差更大，所以交互界面仅开放0.05/0.10两档。目标速度不等于实际速度，快档仍需分别核对方向、停止和速度跟踪。

速度选择使用8/9，因为0–5是MuJoCo原生几何显示开关；当前机器人可视网格在group2，按2会隐藏它们。原生绑定见 [MuJoCo simulate源码](https://github.com/google-deepmind/mujoco/blob/main/simulate/simulate.cc)。

实际生产键盘类验证：快档30秒平均机身前进速度约0.139m/s，慢档约0.038m/s；快档位移3.448m，全程世界坐标横向偏移最大约3.7cm。70秒8/9换档、转向、停止及重置无翻倒，最大倾角4.87°；X后的前进均速接近零，旧航向反馈爬行问题消失。30项单元/契约测试通过。详细记录见 [speed-keyboard-results.json](speed-keyboard-results.json)。目标0.10仍超跟踪约39%，机身相对航向/横向速度仍有残差，不代表精确轨迹控制或实机验证。

先点击窗口：`x` 逐渐减速到站立，`r` 重置并立即清掉运动目标，`q` 退出。方向键是锁存的目标设置，松手不会清零。旧19关节模型的独立转头/下蹲动作没有注册到当前14关节仿真。此前的原始参数和全范围输入保留在 `make sim-raw`，其行走稳定性仍未通过。

物理回归已验证单按上键与连按10次上键各运行30秒不倒，目标速度均限制为0.05m/s。测试证明受限前进的运行条件，不能证明后退/转向精确：独立对照中后退几乎没有达到目标速度，原地转向也存在方向和速度误差。没有调整策略权重、关节轴、硬件默认增益或保护阈值。

2026-10-10更新：26项部署单元/契约测试通过，80秒真实按键回调序列（前进、缓停、后退、原地转向、混合转向、重置）无翻倒，真实GUI上键操作也已验证。详细参数、逐场景结果和跟踪限制见 [keyboard-sim-results.json](keyboard-sim-results.json)。新的命令应包含 `--low-speed-keyboard --policy-kp 200`，终端输出 `LOW-SPEED KEYBOARD INPUT`；已运行的旧进程必须退出后重新启动，代码修改不会自动改变它的参数。

macOS启动入口会从当前Python运行环境查找共享库路径，再启动 `mjpython`，解决uv Python的 `libpython3.12.dylib` 加载问题。

只想观看已验证参数下的低速行走，请在 `microduck/` 运行：

```sh
make demo
```

这会打开30秒的固定前进演示：先站立2秒，再用2秒渐进加速至目标0.05m/s，使用KP200、高度0.12m、时间步0.005s，取消模拟传感延迟。正常1.5秒启动插值保留，未使用即时策略。修复后1500周期实测最低高度0.11537m、无低高度记录；仍有速度误差和横漂，不代表转弯、后退或实机通过。按 `x` 改为站立、`r` 重置并重放、`q` 退出；演示中方向键不改变速度，30秒控制周期完成后自动退出。日志保存于 `microduck/logs/gui-demo.jsonl`。

`make sim-raw` 是原始自由输入调试模式，默认参数下行走仍可能翻倒。其方向键累加且锁存速度，松手不会停止，转弯与前进/后退可同时保留。按 `x` 清零。`r` 和窗口原生Reset均会清零输入，并重置执行器/反馈历史；原生Reset只调整浮动根初始高度，保持关节几何参考值不变。

2026-10-10的有窗口30秒演示实际通过，23项部署回归通过；参数、日志摘要与最大身体倾角见 [gui-walk-demo-results.json](gui-walk-demo-results.json)。演示视角会跟随机器人，防止走出画面。

2026-10-10已在本机实际打开窗口、确认机器人完整显示并运行站立策略。新增库路径与真实14关节重置回归后，20项部署测试、4项训练测试及10秒站立/CPU短步进复验通过。本次本地复验日志位于 `.omx/artifacts/preflight/20261009T164520506324Z/`（目录时间为UTC）。

## 在另一台电脑安装

需要 `uv` 和 Python 3.12。两个目录各有保存的 `uv.lock`，按验证时的依赖版本安装：

```sh
cd microduck
uv sync --locked --group sim --python 3.12
cd ../mjlab_microduck
uv sync --locked --python 3.12
cd ..
python3 scripts/local_preflight.py --training
```

部署侧使用 BAM 1.0.2、MuJoCo 3.15.0、ONNX Runtime 1.31.0。训练侧使用 MjLab1.3.0、Warp1.12.0、Git BAM1.0.0，Git提交固定在锁文件中。这两套 BAM API 不完全一致，已分别适配；树莓派上仍须重新安装/验收，Mac通过不证明ARM Linux设备已通过。

本次安装训练 Git 依赖时曾出现网络 TLS 错误，限定此次调用使用 HTTP/1.1 后成功；没有修改全局 Git 配置。

## 修复了哪些实际阻塞

1. 原部署场景是另一个19执行器模型，缺少策略需要的踝关节等名称；训练端 `robot/`、`actuator/` 模块也缺失。恢复了 Pollen 官方14关节 walk 模型和38份真实网格，原19执行器资产保留。源提交、网格哈希、许可和本地适配见 [MODEL_SOURCE](../microduck/src/model/mjcf/microduck_14dof/MODEL_SOURCE.md)。
2. BAM给MuJoCo的是扭矩，但原XML执行器把它作为目标位置，造成额外 `−0.55*q` 力矩。现在受控执行器使用直接力矩模式，保留电流/力矩限幅；零扭矩、指定扭矩、超范围限幅都有真实物理回归。
3. 适配 BAM 初始化、浮动根DOF摩擦索引、电压跌落单位、模拟电流读回和重置；有限控制周期每次推进物理。过流保护没有取消。
4. 模型/策略路径改为从文件位置定位，可从仓库根运行；策略检查关节次序、观测/动作尺寸、默认姿势及有限数值。
5. 训练侧补齐README和BAM字段展开兼容事件，完成真实CPU环境验证；导出时明确拒绝旧18关节权重，不裁剪或伪造权重。
6. 校准UI默认安装四元数与部署常量对齐；示例用户名改为发布镜像的 `user`。实际安装方向仍须测量确认。
